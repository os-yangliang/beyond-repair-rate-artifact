# Task-paired intervals for the closed BigCodeBench comparison

This is a **post-hoc secondary analysis**, specified on 28 October 2026 before computing these intervals. The original outcomes and point estimates were already known. It is not a preregistration of the experiment and does not change its intake, stopping decisions, outcomes, or costs.

The only input is the already public, sanitized BigCodeBench transition projection, SHA-256 `4502552cd74dd873252f4c9711dbe7fd402d3623559e8b48e3701723c95aae61`. No model, candidate, test, service or hidden content is accessed. The copied input retains its original bytes, including dated publication metadata.

For each task and service, subtract C0-normalized from C1-normalized within each of the three repetitions, then take their arithmetic mean. The reported point estimate gives tasks equal weight. Preserve all 29 tasks, including local-refusal task 989. Repeat the analysis for the 23 tasks that initially fail both public pools. The six C1-P0-passing tasks receive descriptive summaries only. This pre-generation stratum is not chosen from repair success.

Use 20,000 paired task-bootstrap draws and seed 20261028. Draw 29 tasks with replacement for the full cohort and 23 for the repair-feedback stratum, keeping the two policies, services, endpoints and cost fields of each selected task together. Use one fixed pseudorandom stream in the order all tasks, then repair-feedback tasks. Each draw's indices apply to every metric and service in that stratum. Report two-sided 95% percentile intervals, with type-7 linear interpolation at probabilities 0.025 and 0.975. Primary outputs are first/final complete-endpoint differences in percentage points and total logical-token differences per task–repetition. Secondary continuation and HTTP components are specified in the JSON plan.

Validate source identity and pair completeness before resampling. Check original point estimates and stratum decomposition, compare the quantile calculation with the standard-library inclusive-quantile routine, and compare simulated means/variances with exact empirical-bootstrap moments. Keep zero-variance results explicit. Report no p-values or equivalence conclusions. The interval method is fixed here; it will not be switched after seeing interval widths or zero crossings.

These are exploratory, pointwise intervals under task resampling. They characterize heterogeneity in this selected cohort under an exchangeable-task approximation. They do not make the C0-failure-selected tasks representative of all bugs, infer a preferred partition in general, or add independent tasks. The exact finite-cohort averages are already observed; the intervals are not uncertainty about those recorded averages. Three collected repetitions are averaged, not resampled as new independent tasks. New within-task generation variability and rolling-service drift are outside the interval calculation. Provider token units and HTTP components are not common monetary costs or end-to-end latency.

No analysis is performed on the two-task QuixBugs panel, and no historical experimental window is reopened. Detailed choices are frozen in `analysis_plan.json`.
